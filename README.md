# Hikone Cloud Score App

滋賀県彦根市での天体撮影判断を補助する、フロントエンドのみの Open-Meteo ビューアです。

このアプリは個人用の天体撮影判断補助であり、気象予報業務ではありません。

## 使い方

`index.html` をブラウザで開くと、Open-Meteo から今後 7 夜分の hourly 予報をまとめて取得し、選択した評価日の 18:00 から翌朝 06:00 までの詳細を表示します。

- 地点: 登録済み 13 地点から選択
- 評価日: 今日の夜、明日の夜、明後日の夜、日付指定から選択
- 週間表示: 今後 7 夜の総合スコア、判定、おすすめ時間帯、信頼度をカード表示
- 取得モデル: Open-Meteo Best Match、JMA、GFS
- 表示: A-E 総合判定、おすすめ時間帯、賭け候補時間帯、モデル別スコア、雲量折れ線グラフ、時系列テーブル
- 取得項目: `cloud_cover`, `cloud_cover_low`, `cloud_cover_mid`, `cloud_cover_high`, `temperature_2m`, `relative_humidity_2m`, `dew_point_2m`, `precipitation`

上部の週間カードを押すと、その夜の詳細へ即座に切り替わります。評価日を切り替えると、対象夜間は選択日の 18:00 から翌朝 06:00 に変わります。`全地点を比較` も現在選ばれている評価日で実行され、天文アプリ連携の `date` パラメータにも選択中の夜の日付を渡します。

## iPhone で確認

同じ Wi-Fi 上の iPhone から見る場合は、このフォルダを簡易サーバーで配信し、Mac または Windows の IP アドレスを iPhone Safari で開きます。

macOS:

```bash
python3 -m http.server 8000
ipconfig getifaddr en0
```

Windows PowerShell:

```powershell
py -3 -m http.server 8000
ipconfig
```

iPhone Safari で `http://<PCのIPアドレス>:8000/` を開きます。

外出先から見たい場合は、静的ファイル一式を GitHub Pages で公開して Safari から開く方法もあります。公開する場合は Open-Meteo へブラウザから直接アクセスする構成であることを確認して運用してください。

## iPhone のホーム画面へ追加

GitHub Pages で公開した URL を iPhone Safari で開くと、ホーム画面からアプリ風に起動できます。

1. Safari で公開 URL を開く
2. 共有ボタンを押す
3. `ホーム画面に追加` を選ぶ
4. 表示名を確認して `追加` を押す

この初版 PWA は `manifest.json` と iPhone 用メタ情報だけを追加した静的構成です。Service Worker はまだ入れていないため、オフライン起動や予報データのキャッシュは後続拡張です。

## 構成

- `js/config.js`: 地点配列、取得項目、モデル設定
- `js/api.js`: Open-Meteo 取得、今後 7 夜分の切り出し
- `js/scoring.js`: `calculateCloudScore(hourlyData)`、時間別スコア、モデル別スコア、夜間総合判定
- `js/ui.js`: サマリー、グラフ、テーブル描画
- `js/app.js`: 起動処理と再取得ボタン

この分割は、将来 `api.js` の取得先を FastAPI に差し替え、FastAPI 側で Open-Meteo レスポンスや SQLite 保存を担当できるようにしてあります。

Best Match は上部カードとグラフで見る参考表示です。判断主軸は JMA/GFS 比較であり、総合スコア、A-E 判定、モデル不一致度、おすすめ時間帯、詳細テーブルは `ensembleModels = ["jma", "gfs"]` に従い JMA と GFS で行います。

今後 7 夜を出すため、Open-Meteo には 8 日分の hourly データをリクエストし、各夜の 18:00 - 翌 06:00 をフロントエンド側で切り出しています。これにより、日付を切り替えても通常は再取得なしで詳細を見直せます。

## 地点を追加

地点は `js/config.js` の `locations` 配列で管理します。追加時は次の形式で 1 件足してください。

```js
{
  id: "new-site",
  name: "新しい候補地",
  latitude: 35.0,
  longitude: 136.0,
  elevation: 100
}
```

最後に選んだ地点 ID はブラウザの `localStorage` に保存され、次回起動時に復元されます。

## 天文アプリ連携

選択地点の詳細と地点比較カードには `この地点で天文条件を見る` ボタンがあります。ボタンは公開済みの `hikone-astro-app` を開き、次の URL パラメータで撮影地を渡します。

- `site`: 地点名
- `lat`: 緯度
- `lon`: 経度
- `elev`: 標高
- `date`: 日本時間の評価日 `YYYY-MM-DD`
- `time`: 初期時刻 `21:00`
- `return`: 雲量アプリの現在 URL
- `cloudScore`: 雲量スコア
- `cloudGrade`: 総合判定 A-E
- `reliability`: 信頼度
- `bestWindow`: おすすめ時間帯
- `gambleWindow`: 賭け候補時間帯

URL は `URLSearchParams` で生成し、日付は UTC 変換を使わず日本時間の日付で渡します。

## SCW / GPV 確認リンク

選択地点の詳細カードには `SCWで確認` と `GPVで確認` ボタンがあります。地点比較カードにも小さな `SCW` / `GPV` リンクを表示し、選択中の地点名・緯度・経度を付けた外部確認用 URL を新しいタブで開きます。

この連携は外部サイトを手動確認するためのリンクです。SCW の有料会員データは自動取得せず、ログイン Cookie を使った取得、画像タイルや内部 API の解析・スクレイピングは行いません。SCW や GPV の利用規約に従って利用してください。

## 地点比較

通常の `再取得` は選択中の 1 地点だけを更新します。`全地点を比較・おすすめ表示` を押すと、比較結果の先頭に登録地域のおすすめを表示します。全12時間のJMA/GFSが揃った地点だけを対象にし、欠測があれば暫定順位、同点なら併記、最高点が55点未満ならおすすめなしとします。候補地を見比べたいときだけ `全地点を比較` を押してください。

- 登録済み地点を順番に取得し、総合スコアが高い順に比較カードを並べる
- 比較カードでは判定、総合スコア、おすすめ、賭け候補、信頼度、最大モデル差、主な注意を確認できる
- 現在選択中の地点は強調表示される
- 比較カードの地点名を押すと、その地点の詳細表示へ切り替わる

## スコアの考え方

スコアは気象予報ではなく、撮影可否を見比べるためのヒューリスティックです。

- 雲量を中心に減点し、低層雲をやや重く扱う
- 降水がある時間は強く減点する
- 高層雲・湿度・露点差から透明度の目安（推定）を計算し、最大20点減点する。従来の湿度減点はこの項目に置き換える
- A-E 判定はJMA/GFSの時間別平均を、23〜3時は重み4、21〜23時・3〜4時は1、18〜21時・4〜6時は0.5で加重平均して作る（日本時間、終了時刻を含まない12時間）
- おすすめ時間帯は JMA/GFS 平均スコアが高い時間帯で、平均スコアが 70 点以上の連続区間から選び、D/E 判定なら出さない
- 賭け候補は JMA または GFS の片方のモデルだけ良い時間帯を表示する
- 高層雲が多い時間は `薄雲注意`、湿度が高く気温と露点の差が小さい時間は `結露注意` を出す
- 露点差は結露注意と透明度の目安に使用する。透明度は実測の透過率ではなく、黄砂・煙・エアロゾル・上空の水蒸気は未評価
- 同時刻の JMA と GFS の総雲量差を詳細テーブルへ集約し、`安定`、`やや不一致`、`予報割れ`、`大きく不一致` で読む

おすすめ時間帯は、連続区間の「時間別スコア × 時間の重み」の合計が最大の区間を選びます。計算仕様・限界・検証方法は [SCORING.md](SCORING.md) を参照してください。

予報割れが大きい場合は、衛星画像と現地の空確認が必須です。
